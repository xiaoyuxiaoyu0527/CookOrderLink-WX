# CookOrderLink 家庭烹饪小程序 产品设计文档

## 1 项目概述
### 1.1 项目定位
面向家庭多人共用的食材库存+点餐做菜小程序，实现**食材库存管理、在线点菜、接单做菜、食材过期提醒**全流程闭环。

### 1.2 核心目标
- 统一管理家庭食材库存，自动识别临期、过期食材
- 支持家庭成员自助点菜、专人接单烹饪
- 做菜完成自动扣减食材库存，留存操作流水
- 临期食材消息提醒，减少食材浪费

### 1.3 用户角色
- 普通成员：查看菜谱、点菜、查看订单
- 烹饪者：接单做菜、处理订单状态
- 管理员：维护食材库存、家庭成员管理、权限配置

## 6 核心功能详情
### 6.1 点菜功能
#### 功能说明
用户在点菜页浏览所有家庭菜谱，依据当前食材库存判断是否可点，支持勾选多菜品、添加口味备注并提交订单。

#### 页面展示
- 菜品卡片：图片、菜名、简介、预计烹饪时长、状态标签
- 状态：可点 / 库存不足置灰不可点
- 底部栏：已选数量、总时长、提交按钮

#### 点菜流程

点菜页
→ 浏览菜谱列表
→ 系统校验食材库存，标识可点状态
→ 勾选想要菜品
→ 填写口味备注
→ 提交订单
→ 系统二次校验库存
→ 生成订单并推送提醒

## 6.2 厨房接单与做菜功能

### 功能说明
做饭者在厨房页查看订单列表，点击订单或菜品进入菜谱详情，按照食材清单和制作步骤完成做菜。

### 厨房页展示
订单列表使用白色工具卡片，圆角 `18px`。
订单按状态分组展示：
- 待做
- 做菜中
- 已完成
- 已取消

### 做菜流程

厨房页
→ 查看待做订单
→ 点击菜品
→ 查看菜谱详情
→ 点击“开始做菜”
→ 系统校验库存
→ 订单状态变为 cooking
→ 做饭者完成做菜
→ 点击“完成做菜”
→ 系统扣减库存
→ 订单状态变为 done

## 6.3 库存管理功能

### 功能说明
库存管理用于维护家庭食材信息，支持搜索、分类筛选、新增、编辑和过期提醒。

### 库存字段
每个食材记录包含：
- 食材名称
- 分类
- 当前数量
- 单位
- 存放位置
- 过期日期
- 库存状态
- 创建时间
- 更新时间

### 库存页功能
- 顶部胶囊搜索框
- 分类标签使用胶囊 chip
- 食材列表使用工具卡片
- 3 天内过期食材高亮提醒
- 已过期食材红色标记
- 库存为 0 的食材自动标记为「已用完」

### 库存状态
| 状态 | 说明 |
|---|---|
| normal | 正常 |
| expiring | 3 天内即将过期 |
| expired | 已过期 |
| out_of_stock | 已用完 |

### 快速录入优化
MVP 中库存编辑页需要尽量降低录入成本：
- 单位快捷选择：个、斤、克、袋、盒、瓶
- 存放位置快捷选择：冷藏、冷冻、常温
- 过期日期快捷选择：今天、明天、3 天后、7 天后
- 分类快捷选择：蔬菜、肉类、蛋奶、调味品、主食、其他

## 6.4 过期提醒功能

### 功能说明
系统每天定时检查家庭库存中 3 天内即将过期的食材，并提醒已订阅提醒的家庭成员。

### 提醒规则
每天上午 9 点
→ 云函数定时触发
→ 查询 3 天内过期的食材
→ 查询已开启提醒的家庭成员
→ 发送微信订阅消息

### 提醒对象
不固定推送给丈夫，而是推送给：
- 开启库存提醒的用户
- 且拥有 canManageInventory 权限的用户

### 订阅消息内容示例
您有 3 件食材即将过期：
番茄、鸡蛋、青菜。
请尽快使用。

### 授权兜底
微信订阅消息需要用户主动授权，因此需要设计兜底机制：
- 在库存页引导用户开启过期提醒。
- 在个人中心展示提醒开关。
- 未授权时，通过小程序内红点或顶部提示展示过期信息。

## 9.2 状态流转
pending → cooking → done

## 9.3 权限规则
- 拥有 canCook 权限的用户可以将订单从 pending 改为 cooking。
- 拥有 canCook 权限的用户可以将订单从 cooking 改为 done。
- 订单创建者可以在 pending 状态下取消订单。
- 订单进入 done 后不可再取消。
- 所有订单操作都需要校验 familyId。

## 10.1 MVP 策略
MVP 采用「完成做菜时扣减库存」策略。

原因：
- 实现简单
- 用户理解成本低
- 避免开始做菜后取消导致库存被提前占用

扣减流程：
用户点击完成做菜
→ 云函数读取订单
→ 查询订单中菜品对应食材
→ 校验库存是否足够
→ 库存足够则扣减
→ 更新订单状态为 done
→ 记录库存流水

注意事项：
为了降低并发问题，需要在三个节点进行库存校验：
1. 提交订单时校验库存。
2. 开始做菜时再次校验库存。
3. 完成做菜扣减库存时最终校验。

如果最终扣减时库存不足，则提示：
当前库存不足，无法自动完成扣减，请手动调整库存后再完成。

---

## 10.2 后续优化策略
后续版本可以增加库存预占机制：
pending → cooking：预占库存
cooking → done：正式扣减库存
cooking → cancelled：释放预占库存

对应库存字段可扩展：
{
  "quantity": 10,
  "reservedQuantity": 2,
  "availableQuantity": 8
}

## 12. 云函数设计

### 12.1 createOrder
功能：创建订单。
流程：
校验用户 familyId
→ 校验用户是否有 canOrder 权限
→ 校验菜品是否存在
→ 校验库存是否充足
→ 创建订单
→ 给做饭者发送新订单订阅消息

### 12.2 updateOrderStatus
功能：更新订单状态。
流程：
校验用户 familyId
→ 校验订单 familyId
→ 校验用户权限
→ 校验状态流转是否合法
→ 如果变更为 cooking，则再次校验库存
→ 如果变更为 done，则扣减库存
→ 更新订单状态

### 12.3 deductInventory
功能：根据订单中的菜品食材扣减库存。
流程：
读取订单
→ 读取菜谱
→ 汇总所需食材数量
→ 校验库存是否充足
→ 扣减库存
→ 写入库存流水
→ 更新库存状态

### 12.4 checkExpiringInventory
功能：每日检查即将过期食材。
触发方式：每天上午 9 点定时触发
流程：
查询 3 天内过期食材
→ 按 familyId 聚合
→ 查询有库存提醒权限且已订阅的用户
→ 发送微信订阅消息
→ 更新食材状态为 expiring 或 expired

### 12.5 updateInventoryStatus
功能：更新库存状态。
状态规则：
quantity <= 0 → out_of_stock
expireDate < today → expired
expireDate <= today + 3 天 → expiring
其他 → normal

## 13. 异常处理

### 13.1 库存不足
发生场景：
- 点菜页实时查询时发现库存不足
- 提交订单时库存不足
- 开始做菜时库存不足
- 完成做菜扣减库存时库存不足

处理方式：
- 点菜页置灰显示「暂不可点」
- 显示缺少的食材和数量
- 提交订单失败时提示具体原因
- 完成做菜时扣减失败，需要提示用户手动调整库存

提示示例：
当前库存不足，无法自动完成扣减，请手动调整库存后再完成。

### 13.2 过期食材
处理方式：
- 3 天内过期：橙色标记
- 已过期：红色标记
- 已过期食材默认不参与可点判断
- 用户可手动编辑或删除过期食材

### 13.3 订单取消
规则：
- pending 状态允许订单创建者取消。
- cooking 状态允许做饭者取消，但需要填写取消原因。
- done 状态不可取消。

### 13.4 数据隔离
规则：
- 所有业务数据必须包含 familyId。
- 所有查询必须带上当前用户的 familyId。
- 云数据库安全规则确保用户只能访问自己家庭组的数据。
- 云函数内部也必须二次校验 familyId，不能只依赖前端传参。

### 13.5 微信订阅消息未授权
处理方式：
- 在提交订单或进入库存页时，引导用户开启订阅消息。
- 未授权时，不影响主流程。
- 使用小程序内红点、顶部 banner 作为兜底提醒。

## 17. 关键风险与应对

### 17.1 库存录入成本高
风险：用户不愿意长期维护库存。
应对：提供常用单位快捷选择、过期日期快捷选择、存放位置快捷选择；后续支持拍照、扫码、语音录入。

### 17.2 微信订阅消息触达不稳定
风险：用户未授权订阅消息，导致提醒无法送达。
应对：在关键页面引导开启订阅；不强依赖推送，使用小程序内红点、banner 兜底。

### 17.3 角色过于固定
风险：只适用于固定角色分工，不利于扩展。
应对：采用权限组合模式，支持一人多权限。

### 17.4 库存并发扣减
风险：多人同时操作导致库存扣减异常。
应对：三次校验库存；后续引入库存预占机制。

## 18. 验收标准

### 18.1 点菜链路
- 用户可以看到菜品列表
- 库存不足菜品不可选择
- 用户可以勾选菜品并提交订单
- 提交订单时会再次校验库存
- 订单创建后厨房页可见

### 18.2 做菜链路
- 做饭者可以看到待做订单
- 可以进入菜谱详情
- 可以将订单改为做菜中
- 可以完成订单
- 完成订单后库存自动扣减

### 18.3 库存链路
- 用户可以新增食材
- 用户可以编辑食材
- 用户可以搜索食材
- 用户可以按分类筛选食材
- 快过期食材会高亮
- 库存为 0 时自动标记已用完

### 18.4 提醒链路
- 云函数可以每天定时执行
- 可以查询 3 天内过期食材
- 可以向已授权用户发送订阅消息
- 未授权时页面内仍有提醒展示

### 18.5 数据安全
- 用户只能访问自己家庭组的数据
- 所有订单、库存、菜谱都按 familyId 隔离

## 19. 总结

CookOrderLink 的核心价值是把家庭做饭中的几个动作连接起来：
想吃什么 → 家里有什么 → 谁来做 → 怎么做 → 用掉了什么 → 什么快过期

V1.0 应优先保证这个闭环简单、稳定、可用。
产品设计上保留家庭协作的温馨感，技术设计上采用通用权限模型。
第一版重点打磨：点菜体验、厨房订单体验、库存维护体验、自动扣库存、过期提醒。
只要主流程顺畅，后续可自然扩展高级功能。
