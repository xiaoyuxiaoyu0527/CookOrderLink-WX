# CookOrderLink - 家庭烹饪协作微信小程序设计文档

## 1 项目概述

### 1.1 项目定位
面向夫妻的家庭烹饪协作微信小程序，实现**食材库存管理、在线点菜、接单做菜、食材过期提醒**全流程闭环。

### 1.2 核心目标
- 统一管理家庭食材库存，自动识别临期、过期食材
- 妻子点菜、丈夫接单烹饪，分工协作
- 做菜完成自动扣减食材库存
- 临期食材消息提醒，减少食材浪费

### 1.3 用户角色
- 妻子（点菜者）：浏览菜谱、点菜、查看订单状态
- 丈夫（烹饪者）：接单做菜、管理食材库存、处理订单

### 1.4 技术栈
- 原生微信小程序 + 微信云开发
- 设计语言：Apple Design System（产品优先、UI 退隐）

---

## 2 整体架构

### 2.1 业务模块
1. 菜谱模块 — 菜品数据管理
2. 点菜订单模块 — 浏览、选菜、提交订单
3. 厨房做菜模块 — 接单、做菜、完成
4. 食材库存模块 — 录入、编辑、搜索、过期管理
5. 消息提醒模块 — 新订单提醒、过期提醒
6. 家庭组模块 — 邀请码绑定、数据隔离

- 底部 Tab：点菜页 / 厨房页

## 5 核心功能详情

### 5.1 点菜功能

**功能说明：**
妻子在点菜页浏览所有家庭菜谱，依据当前食材库存判断是否可点，支持勾选多菜品、添加口味备注并提交订单。

**页面展示：**
- 菜品卡片：图片、菜名、简介、预计烹饪时长、状态标签
- 状态：可点 / 库存不足置灰不可点
- 底部固定操作区：已选数量、总预计时长、提交按钮

**点菜流程：**
```
点菜页 -> 浏览菜谱列表
       -> 系统校验食材库存，标识可点状态
       -> 勾选想要菜品
       -> 填写口味备注
       -> 提交订单
       -> 系统二次校验库存
       -> 生成订单并推送提醒给丈夫
```

### 5.2 厨房接单与做菜功能

**功能说明：**
丈夫在厨房页查看订单列表，点击订单或菜品进入菜谱详情，按照食材清单和制作步骤完成做菜。

**厨房页展示：**
- 订单按状态分组：待做 / 做菜中 / 已完成 / 已取消
- 订单卡片：下单人、菜品名称、备注、状态标签、创建时间
- 顶部库存预警卡片 + 底部库存管理入口（有快过期食材时显示红点）

**做菜流程：**
```
厨房页 -> 查看待做订单
       -> 点击菜品 -> 查看菜谱详情
       -> 点击"开始做菜"
       -> 系统校验库存
       -> 订单状态变为 cooking
       -> 完成做菜
       -> 点击"完成做菜"
       -> 系统扣减库存
       -> 订单状态变为 done
```

### 5.3 库存管理功能

**功能说明：**
丈夫录入、编辑食材库存信息，支持搜索、分类筛选、新增、编辑和过期提醒。

**库存字段：**
食材名称、分类、当前数量、单位、存放位置、过期日期、库存状态、创建时间、更新时间

**库存状态：**

| 状态 | 说明 | 视觉标记 |
|------|------|---------|
| normal | 正常 | 无特殊标记 |
| expiring | 3 天内即将过期 | 橙色标记 |
| expired | 已过期 | 红色标记 |
| out_of_stock | 已用完（数量=0） | 灰色标记 |

**快速录入优化（降低录入成本）：**
- 单位快捷选择：个、斤、克、袋、盒、瓶
- 存放位置快捷选择：冷藏、冷冻、常温
- 过期日期快捷选择：今天、明天、3 天后、7 天后
- 分类快捷选择：蔬菜、肉类、蛋奶、调味品、主食、其他

### 5.4 过期提醒功能

**提醒规则：**
```
每天上午 9 点 -> 云函数定时触发
              -> 查询 3 天内过期的食材
              -> 查询已开启提醒的用户
              -> 发送微信订阅消息
```

**提醒对象：** 开启了库存过期提醒的用户（不固定推送给某一方）

**订阅消息内容示例：**
> 您有 3 件食材即将过期：番茄、鸡蛋、青菜。请尽快使用。

**授权兜底：**
- 在库存页引导用户开启过期提醒
- 在个人中心展示提醒开关
- 未授权时，通过小程序内红点或顶部提示展示过期信息

## 6 用户角色与流程

### 6.1 家庭组流程

```
用户首次进入 -> 创建家庭组或输入邀请码加入
            -> 设置昵称和头像
            -> 进入小程序首页
```

- 创建家庭组：系统生成 familyId + 邀请码，创建者自动成为管理员
- 加入家庭组：输入邀请码 -> 校验 -> 加入 -> 成为成员

### 6.2 订单状态流转

| 状态 | 说明 |
|------|------|
| pending | 待做 |
| cooking | 做菜中 |
| done | 已完成 |
| cancelled | 已取消 |

**状态流转规则：**
```
pending  -> cooking   （丈夫点击"开始做菜"）
pending  -> cancelled （妻子取消订单）
cooking  -> done      （丈夫点击"完成做菜"，自动扣减库存）
cooking  -> cancelled （丈夫取消，需填写原因）
done     -> 不可再操作
```

### 6.3 库存扣减策略（MVP）

MVP 采用「完成做菜时扣减库存」策略：
- 实现简单，用户理解成本低
- 避免开始做菜后取消导致库存被提前占用

**三点库存校验：**
1. 提交订单时校验库存（前端展示可点状态）
2. 开始做菜时再次校验库存（防止期间库存被消耗）
3. 完成做菜扣减库存时最终校验

如果最终扣减时库存不足，提示：
> 当前库存不足，无法自动完成扣减，请手动调整库存后再完成。

**后续优化：** 引入库存预占机制（pending->cooking 预占，cooking->done 正式扣减，cooking->cancelled 释放预占）

## 8 云函数设计

### 8.1 userLogin
触发：小程序启动
功能：获取 openid，创建/更新用户信息

### 8.2 createFamily
触发：手动调用
功能：生成家庭组 + 6 位邀请码，创建者成为管理员

### 8.3 joinFamily
触发：手动调用
功能：校验邀请码，加入家庭组

### 8.4 createOrder
触发：手动调用
流程：
```
校验用户 familyId
-> 校验菜品是否存在
-> 校验库存是否充足
-> 创建订单
-> 给丈夫发送新订单订阅消息
```

### 8.5 updateOrderStatus
触发：手动调用
流程：
```
校验 familyId
-> 校验状态流转是否合法
-> 如果变更为 cooking：再次校验库存
-> 如果变更为 done：扣减库存
-> 如果扣减失败：提示手动调整
-> 更新订单状态
```

### 8.6 updateInventoryStatus
触发：手动调用 + 定时触发
状态规则：
```
quantity <= 0           -> out_of_stock
expireDate < today      -> expired
expireDate <= today + 3 -> expiring
其他                     -> normal
```

### 8.7 checkExpiringInventory
触发：每天上午 9 点定时
流程：
```
查询 3 天内过期食材
-> 按 familyId 聚合
-> 查询已开启提醒的用户
-> 发送微信订阅消息
```

## 9 异常处理

### 9.1 库存不足

| 场景 | 处理方式 |
|------|---------|
| 点菜页浏览时 | 置灰显示「暂不可点」，显示缺少的食材和数量 |
| 提交订单时 | 提交失败，提示具体原因 |
| 开始做菜时 | 阻止操作，提示库存不足 |
| 完成做菜扣减时 | 提示"请手动调整库存后再完成" |

### 9.2 过期食材

| 状态 | 视觉标记 | 行为 |
|------|---------|------|
| 3 天内过期 | 橙色标记 | 可参与点菜 |
| 已过期 | 红色标记 | 不参与可点判断 |
| 已用完 | 灰色标记 | 不参与可点判断 |

### 9.3 订单取消
- pending 状态：妻子可直接取消
- cooking 状态：丈夫可取消，需填写取消原因
- done 状态：不可取消

### 9.4 数据隔离
- 所有业务数据必须包含 familyId
- 所有查询必须带上当前用户的 familyId
- 云数据库安全规则确保用户只能访问自己家庭组的数据
- 云函数内部二次校验 familyId，不依赖前端传参

### 9.5 微信订阅消息未授权
- 在提交订单或进入库存页时引导开启订阅
- 未授权不影响主流程
- 使用小程序内红点、顶部 banner 作为兜底提醒

## 13 关键风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 库存录入成本高 | 用户不愿长期维护 | 快捷选择降低摩擦；后续支持拍照/扫码录入 |
| 订阅消息触达不稳定 | 提醒无法送达 | 关键页面引导授权；小程序内红点/banner 兜底 |
| 库存并发扣减 | 扣减异常 | 三点校验；后续引入预占机制 |
| 菜谱数据冷启动 | 初期无菜品可点 | 预置几道家常菜谱模板 |

## 14 总结

CookOrderLink 的核心价值链：
**想吃什么 -> 家里有什么 -> 谁来做 -> 怎么做 -> 用掉了什么 -> 什么快过期**

V1.0 优先保证这个闭环简单、稳定、可用。技术设计上保持简洁（简单角色模型、无流水表），视觉设计上遵循 Apple Design System。第一版重点打磨：点菜体验、厨房订单体验、库存维护体验、自动扣库存、过期提醒。主流程顺畅后，后续可自然扩展高级功能。
